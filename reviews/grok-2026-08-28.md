# Grok review of UI Compose v0.3

Reviewer: Grok Build, 2026-08-28
Target: `983033995/ui-lego#1` (`refactor/ui-compose-v0.2`)
Purpose: a second-opinion patch for GPT to implement against. Do not treat this file as product surface area. Fold the accepted changes into `SKILL.md` / `references/` / `evals/`, then delete this review.

## Verdict

**Keep the architecture. Put the recipes back. Do not merge #1 as a stable skill yet.**

The product thesis in #1 is correct for a *portable* skill:

> Detect the host. Learn traits from proven products. Re-express them with the host's own primitives. Measure the decision, not the README.

That is the right moat. Growing a shopping list of Magic UI / Aceternity / shadcn is the wrong moat.

v0.3 over-corrected from **Lego cookbook** to **composition taxonomy**. Agents follow short imperative recipes. YAML registries and a scoring formula do not ship UI. The original skill's unique value was concrete, stealable physics: caret size, stream-tail blur, nested radii, easing, duration. Those were deleted and replaced with principles. Principles are true. They are also how every generic frontend skill already talks.

If this lands as-is, agents will *describe* composition more accurately and *render* flatter work.

## What to keep from #1

Do not revert these. They are the actual upgrade.

1. **Host Read is mandatory.** Original `ui-lego` assumed TanStack + React + Tailwind + Radix + shadcn. That is correct inside one sandbox and harmful as a public skill.
2. **Libraries are evidence, not default dependencies.** Source / Pattern / Skeleton split is the right knowledge model.
3. **Provenance modes.** Observed-trait vs copy-own vs inspiration-only is required once the skill reverse-engineers live products.
4. **Adapter layer.** React/Tailwind, Vue/Element Plus, Vue/UnoCSS, generic CSS is a good v0 baseline. Add more only when an eval fails.
5. **Real bugs fixed:** tilt `group-hover` without a group parent; editorial campaign mixing React JSX with Vue `v-bind()`; hover-only SKU activation; hidden-CoT wording.
6. **Evals as contracts.** Host fixture + expected skeleton/patterns + hard fails + decision-error classes is the right shape.
7. **Machine-checked registries.** Schema + cross-reference CI is worth keeping.

## What #1 got wrong

### 1. Taxonomy replaced implementation

`ai-primitives.md`, `motion-blocks.md`, `threeui.md`, `reverse-engineering.md` used to be "do this CSS / this mount / this fingerprint". They are now "please notice these states".

A Pattern without a host-neutral recipe is a directory entry. A skill that only has directory entries is a linter for taste, not a composition engine.

**Required shape for every Pattern ID:**

```text
id
jobs / surface / density / motion
structure + required states
host-neutral recipe (CSS / behavior / DOM roles — no React, no Vue, no Tailwind)
adapter hints (optional, short)
evidence source IDs
risks
```

If a Pattern cannot state a recipe in <40 lines, it is not ready to be canonical. Keep it as source research.

### 2. SKILL.md still points at the wrong files

HEAD of #1 still does all of these:

| Location | Bug | Fix |
| --- | --- | --- |
| §0 last paragraph | fallback gates pointed at **§7** (AI surfaces) | point at **§8** |
| §2 | skeleton chosen from `layout-steal.md` only | choose from `references/skeletons/registry.yaml` first; `layout-steal.md` is the human expansion |
| §3 | "pick patterns from the **source** registry" | pick from `references/patterns/registry.yaml` using `references/composition-selection.md` |
| §3 last paragraph | "consult `sources/registry.yaml`" as the pattern step | sources are evidence *after* pattern IDs are chosen |
| Core "read on demand" list | missing `composition-selection.md`, `patterns/registry.yaml`, `skeletons/registry.yaml` | add them; do not make the agent read every file up front |

This branch includes those pointer fixes in `SKILL.md`. GPT should keep them, not re-argue them.

### 3. Fake precision

`references/composition-selection.md` `job_match * 5 + ...` is a ranking mnemonic. It is not Composition Intelligence. Keep the hard rejects. Drop or demote the arithmetic so agents do not pretend they computed a score.

### 4. Anti-slop got vaguer

Original tells that actually fire in production and should return:

- `p-[13px]` / `gap-[17px]` / other ad-hoc spacing off the host scale
- em-dash in UI copy
- numbered eyebrows (`001 · Capabilities`)
- Inter-everywhere with no weight/size hierarchy
- "Live" badges and shimmer on static text
- purple/violet as the silent brand accent

Generic "aurora / glassmorphism / three cards" is necessary but not sufficient. Agents already know those words and still emit them. Specific tokens catch specific failures.

### 5. Evals are contracts without runs

Six markdown fixtures, zero screenshots, zero model-vs-skill comparison. `DELIVERY.md` already admits this. Calling the branch v0.3 "Composition Intelligence" oversells a documentation refactor with a validator.

Do not publish quality claims until eval **01** (Vue + Element Plus orders) and **02** (agent chat) have been run in at least:

- model only
- UI Compose

Capture desktop + ~390px + dependency diff + decision-error class. Until then this is beta architecture, not a release.

### 6. Context budget

SKILL.md is a process essay plus a 14-file reading list. Agents will either skip the YAML or spend the turn reading catalogs.

SKILL.md should stay a **decision pipeline**:

```text
Host Read → Design Read → 1 skeleton → 3–7 patterns → 1 adapter → Verify
```

Everything else is on-demand. The registries are lookup tables, not the first thing the model inlines.

### 7. `compatibility` frontmatter

This repo's `scripts/validate_skill.py` allows `compatibility`. OpenAI/Codex `quick_validate.py` reportedly does not. Do not invent a third validator. Put compatibility prose in the body (or `metadata`) so both packagers accept the file. Local CI should not be the only contract.

## Do not do

- Do not revert Host Read, adapters, provenance, or the three-registry split.
- Do not restore "default to shadcn" / "generate into `src/components/ui`" in the core contract.
- Do not add Ant Design / Svelte / Next adapters until an eval fails without them.
- Do not grow the Source Registry because a site looks cool. A research pass must improve a Pattern recipe, a Skeleton, a provenance note, or an eval hypothesis.
- Do not vendor Linear / Raycast / Beautiful UI identity.
- Do not keep this `reviews/` file after the points are folded in.
- Do not rename the GitHub repo until eval 01 and 02 have real rendered output. `ui-compose` is a fine name; it does not fix bland implementation.

## Relation to original ui-lego

Original ui-lego is a strong **single-stack cookbook**. UI Compose is the right **public-skill** direction. The synthesis is:

```text
ui-lego recipes
  → strip stack-specific syntax
  → attach to Pattern IDs
  → adapt through Host Read
```

Not:

```text
delete the recipes
  → keep the ontology
  → hope the model invents the CSS
```

That second path is how this skill becomes indistinguishable from a generic "make good UI" prompt.
